# Admin Separation And Claim Safety

## Admin Separation

The applicant product and admin/data UI must be structurally distinct:

- Applicant routes use product shell navigation and card/list views.
- `/admin` uses admin/data language and compact status sections.
- Admin/data cannot be the default route.
- Admin tables or data status can exist only behind `/admin` or secondary fallback areas.

## Claim Safety Rules

The product must not say or imply:

- guaranteed admission;
- school-specific acceptance probability or admit chance;
- best school;
- safest school or safe school;
- sure thing;
- public/private quality superiority;
- residency placement superiority;
- curated-list certainty without generated field readiness and caveats.

## Allowed Language

Allowed:

- "score-screen fit";
- "published MCAT/GPA context";
- "generated ranking context";
- "missing data";
- "source confidence";
- "not acceptance probability" as caveat copy.

## Caveats

Use generated copy where available:

```text
MCAT/GPA score-screen fit only; not acceptance probability or a school-specific admit chance.
```

Methodology should explain deterministic scoring and explicitly state that the app does not run a predictive admissions model.
