# Design QA

## Objective

Define how visual work should be reviewed once implementation begins.

## Required QA

- desktop screenshot review;
- mobile screenshot review;
- card text overflow checks;
- filter/control touch target checks;
- source/caveat visibility checks;
- missing-data state checks;
- profile route smoke checks;
- compare and shortlist workflow checks.

## Review Questions

- Does the site feel serious without looking institutionally dated?
- Can an applicant understand the rank, fit, cost, and source confidence in one scan?
- Is mobile usable without losing the core decision story?
- Are missing data and caveats honest?
- Are admin and applicant-facing surfaces visually distinct?
- Does the design avoid fake youth branding?

## Done Criteria

- Screenshots show no overlapping text or broken cards.
- Mobile and desktop layouts both support real school review.
- Visual polish does not hide uncertainty.
