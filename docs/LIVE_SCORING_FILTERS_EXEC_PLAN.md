# Live Scoring And Filter Controls Executive Plan

## Objective

Make Build My List feel like a real product decision tool instead of a static ranked spreadsheet.

The next slice adds browser-local live scoring and stronger exclusion/filter controls to the Astro React frontend while preserving the existing Python pipeline as the source of truth for baseline generated data.

## Product Outcome

Applicants should be able to answer:

```text
Given my current MCAT, GPA, state, cost sensitivity, geography exclusions, and score weights, which schools should I review first?
```

The answer must update live in the browser without a server, database, private writeback, or admissions-probability claim.

## Current State

- `frontend/` is a static Astro app with React islands.
- The payload contains 233 schools.
- Build My List uses local browser state for applicant inputs and lists.
- Current MCAT/GPA inputs affect filters and score-screen fit labels, but they do not recompute the displayed rank.
- Current score/rank fields are generated by the Python pipeline:
  - `overall_school_value`
  - `admissions_score`
  - `attendance_score`
  - `decision_rank`
- There are in-progress UI changes that must be preserved:
  - larger Build My List card count with Load More / Show All;
  - Recommendations collapsed into Build My List;
  - Not Interested list/tab and card action.

## Product Contract

- Default route remains `/` Build My List.
- Build My List must show both:
  - `Your Rank`: live browser-computed rank from current inputs and weights.
  - `Baseline Rank`: generated pipeline rank from the payload.
- Live scoring may reorder Build My List.
- Baseline rank must remain visible for auditability.
- State/city exclusions must remove schools from the active Build My List view without deleting them.
- Not Interested must remain browser-local and reversible.
- Score-weight changes must update live ranking in the browser.
- All computations must be deterministic and visible in methodology.
- Data-confidence/source-confidence may remain visible as provenance, but it is not a user-facing filter in this slice.

## Non-Goals

- No predictive admissions model.
- No school-specific acceptance probability.
- No “likely admitted,” “safe school,” “guaranteed,” or “best school” claims.
- No scraping or new data-source ingestion.
- No database or Vercel/Postgres migration.
- No private applicant data committed to the repo.
- No rewrite of the Python scoring pipeline in this slice.
- No data-confidence filter controls for now.

## Execution Slices

1. Finish current UI cleanup:
   - Recommendations is not a primary nav tab.
   - Not Interested tab/page works.
   - Not Interested removes schools from Build My List and from Interested/Applying/Compare.
   - remove any remaining data-confidence filter state/control/copy while preserving confidence fields as read-only transparency.
   - Existing screenshot artifacts remain untouched.

2. Add exclusion controls:
   - state multi-select exclusion;
   - city dropdown exclusion built from payload city/state pairs;
   - institution ownership filter: Public, Private, Unknown;
   - quick chips for excluded states/cities;
   - quick exclude for Texas if requested by the user;
   - clear-all exclusions;
   - counts showing `shown / eligible / total`.

3. Add live scoring controls:
   - MCAT and GPA inputs;
   - state of residence;
   - state-first default view for Florida/current selected state;
   - component-weight controls in the Build My List menu;
   - reset-to-default weights;
   - optional preset buttons only if the labels are neutral and non-claimy;
   - if presets are included, make `State-first` and `Florida-first` distinct and plainly described.

4. Add live scoring engine:
   - `frontend/src/lib/live-scoring.ts`;
   - deterministic formulas aligned with Python where possible;
   - live score/rank rows derived from payload + preferences;
   - contribution rows for explanations.

5. Update cards:
   - Your Rank;
   - Baseline Rank;
   - Your Score;
   - live MCAT/GPA/state/cost contribution bullets;
   - warning when live score coverage is low.

6. Update methodology and smoke checks:
   - document formulas;
   - explain live vs baseline;
   - prevent unsupported admissions claims;
   - verify new routes/labels exist.

## Verification

Run:

```bash
cd frontend
npm run build
npm run smoke
cd ..
uv run med-school-validate
uv run pytest
git diff --check
```

Frontend smoke must additionally verify:

- Build My List includes `Your Rank`.
- Build My List includes `Baseline Rank`.
- Methodology includes live scoring formulas.
- Not Interested route exists.
- Data-confidence is not present as a filter/control.
- Ownership filter does not make unsupported public/private quality claims.
- Unsupported claims are absent.
- No routine visible Hide controls return.

## Done Criteria

- A user can exclude states and cities without losing data.
- A user can filter public/private/unknown only when the payload exposes source-backed ownership labels or clearly labels missing ownership as Unknown.
- A user can change scoring weights live and see rank order change.
- A user can distinguish live personalized score from generated baseline score.
- Methodology explains exactly what changed and what did not.
- Headless worker can execute without human intervention after design questions are resolved.
